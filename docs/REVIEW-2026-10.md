# External review, October 2026: findings and status

Six independent reviews (security and operations, radio design, DVB-S2,
DVB-T2, DATV FPGA cores, narrowband DSP) read the whole tree on
2026-10-01. This file records what was found and what was done about it.

## Open on purpose (to fix later)

- **Default passwords.** The web UI ships `password = "testing"`
  (package/trxd/trxd.toml), root's password is `analog` (defconfigs) and
  Dropbear allows root password login (`MAX_UNAUTH_PER_IP` 20). Fix: ship an
  empty web password (trxd then generates one), lock root's password and
  use keys only, show the generated password on the console / USB drive.
  The web password file is still written with default permissions.
- **TCI and rigctld need no login** and listen on all interfaces with
  `allow_tx = true`: anyone on the LAN can key the transmitter through them
  (inside `trx.tx_ranges`, see below). Until fixed: firewall the board or
  reach it over WireGuard only, or set `tci_bind` / `rigctl_bind` to
  `127.0.0.1`.
- Web sessions survive a password change until reboot.
- Firmware images are not signed (SHA256SUMS sits in the same zip).
- The self-signed web certificate has no pinning/fingerprint display.

## Done

**MQTT removed** (it was an anonymous broker on all interfaces, run as
root, with a command topic that keyed the transmitter). Decodes, beacon-rx
carrier reports and the reference state go to the log; in the trx role
decodes also go to the web UI and TCI. An `[mqtt]` section in an old
trxd.toml is accepted with a warning.

**SSH keys** are restored at boot from where `device_persistent_keys` saves
them (`/mnt/jffs2/root/.ssh`), the old location as a fallback.

**Transmitter interlocks** (src/trxd/src/safety.rs, trx.rs, radio/iio.rs):
- RF off (TX LO powered down, PTT line low) on a panic, on SIGTERM / SIGINT
  / SIGHUP, and when the engine has not ticked for 2 s while RF is on
  (stalled RX DMA). S80trxd forces RF off before every (re)start and on stop.
- `trx.tx_ranges`: transmit only inside these ranges, whole occupied band
  (DATV: the signal's width). Default: IARU Region 1 amateur allocations
  50-54, 70-70.5, 144-146, 430-440, 1240-1300, 2300-2450, 3400-3475,
  5650-5850 MHz. A transverter marked able to transmit adds its band. The
  beacon transmitter's frequency is checked at start, and `allow_tx` applies.
- The TX LO never moves while RF is on: a frequency change that needs it
  (or another transverter, or leaving the allowed ranges) ends the
  transmission first. Small moves inside the stream stay on the NCO.
- One transmit source at a time (a rigctl T1 no longer takes over DATV).
- Keying: PTT line, `ptt_delay_ms`, then the TX LO; unkeying the reverse,
  with the queued RF drained first and the DAC left on silence. The TX LO is
  kept powered down after LO writes while receiving.
- Envelope limiting before the DAC instead of clipping I and Q apart.
- Reference corrections (xo_correction) are applied by the engine thread,
  only while not transmitting, at the LOs it set (no race with retuning).
- DVB-T2's TX filter width is set before RF goes on; unkey retunes (after
  a cross-band split); DATV generated in the FPGA is refused through an
  inverting transverter (it would go out mirrored).
- The web WebSocket is pinged every 5 s and dropped after 15 s of silence,
  which releases a straight key held over a dead link.

**Web server**: request and header lines capped at 8 KiB, the whole request
within 20 s however slowly it trickles, at most 32 connections (8 per
address), failed logins limited to 5 per minute per address, TLS key and
session file mode 0600, transverter names validated and escaped.

**Boot and update** (docs/FLASH.md):
- S99fwconfirm needs the real uplink (not usb0's fixed address) and a
  trxd that stays up.
- A confirmed slot that fails to load boots the other slot for that boot
  (UBOOT_FALLBACK=1); DFU only when both fail.
- The Zynq hardware watchdog is started by the U-Boot script (about 170 s)
  and taken over by S15watchdog.
- The U-Boot environment is backed up to jffs2 on confirmed boots and
  restored on a bad CRC (S20uenv). A redundant environment is not possible:
  U-Boot itself is never updated, and fw_env.config must match it.

**DATV FPGA** (maia-sdr datv-ddc, both Libre bitstreams rebuilt):
LDPC ignores configuration while busy (and trxd never starts it busy; a
stuck engine falls back to software); finished counter and sticky AXI error
bit; DDC mixer/FIR saturate instead of wrapping; ring recorder completes a
burst on stop, raises `finished` when idle, counts wraps (0x7C46001C, used
for overrun detection); T2 equalizer latches gshift with its bank; TX
underflow counter readable (DTX3, 0x43C20010); stale TX control bits
cleared; one lock for the shared DAC GPIO register; every busy wait bounded;
`fpga-mode stop-dma` stops all PL DMA before a bitstream reload and on
S80trxd stop.

**DVB-S2**: the receiver steps over dummy PLFRAMEs and other MODCODs by
their own length, checks MATYPE (TS, single stream, no ISSY/NPD, UPL 1504)
and each user packet's CRC-8; TS mux: PCR within 100 ms from 45.1 kbit/s
up (the lean profile below is a documented exception), EIT sections 25 ms
apart, NIT delivery system descriptor (0x43 for S2, T2 descriptor for T2),
one AUD per access unit; demux handles multi-packet sections, PMT changes,
duplicate packets and the PTS wrap.

**DVB-T2**: L1-post FREQUENCY carries the real frequency (saturating at
4.29 GHz); L1-pre/post are decoded and CRC-checked every frame and a
different configuration is refused; LDPC DDR blocks 128-byte aligned;
router buffer reuse detected. 2.0 and 1.35 MHz are documented as
non-standard (third-party receivers: use 1.7 MHz).

**Narrowband**: slot recorder restarts after a long gap (no zero-fill);
PI4 tone 0 at carrier - 117.1875 Hz by default, optional PI4-CW-carrier
every minute, receive search +-300 Hz; beacon-rx decodes CW only where the
keying is Morse and measures the carrier over the steady part; CESSB only
trims peaks (3 dB) after the speech processor; keyer queues dot units,
512 characters per text; live CW finder and speech processor survive NaN
and odd filters, control messages are never dropped; FPGA network and model
loading have timeouts.

## Not done

- DVB-T2 receiver: scattered-pilot time interpolation, CSI-weighted LLRs and
  per-component demapping of rotated cells need t2eq/t2router/LDPC HDL work
  (docs/DVBT2.md). No third-party receiver has decoded our T2 yet.
- DVB-S2 TX through the FPGA sends no dummy PLFRAMEs when its input runs dry
  (HDL).
- PlutoSky R2 bitstream not rebuilt with the FPGA fixes.
- A watchdog reset while Linux has the W25Q256's upper bank selected can
  still stop the BootROM (as before).
